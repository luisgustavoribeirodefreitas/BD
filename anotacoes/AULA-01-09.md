# Tipos de dados - Banco de Dados

## Números

- **INT / INTEGER** → armazena números inteiros.
  - A disponibilidade e o comportamento podem variar conforme o **SGBD**.
  - Exemplo: `10`, `250`, `-50`

- **TINYINT** → inteiro pequeno, ocupa menos espaço que `INT`.
  - Muito usado para valores pequenos ou flags, dependendo do SGBD.

- **SMALLINT** → inteiro com capacidade maior que `TINYINT` e menor que `INT`.

- **MEDIUMINT** → inteiro intermediário entre `SMALLINT` e `INT`.
  - Disponível em alguns SGBDs, como o **MySQL**.

- **BIGINT** → inteiro para valores muito grandes.
  - Ocupa mais espaço que `INT`.

- **FLOAT** → armazena números com casas decimais.
  - É um tipo de **ponto flutuante**.
  - Pode apresentar pequenas imprecisões.
  - A quantidade de casas decimais **não é definida de forma exata** como no `DECIMAL`.

- **DECIMAL(9,2)** → armazena números decimais com **precisão fixa**.
  - `9` → quantidade **total de dígitos**.
  - `2` → quantidade de dígitos **após a vírgula**.
  - Portanto, sobram `7` dígitos para a parte inteira.
  - Exemplo: `1234567,89`
  - É indicado para valores que exigem precisão, como **preços e valores monetários**.

## Texto

- **CHAR(n)** → armazena uma quantidade **fixa** de caracteres.
  - Exemplo: `CHAR(5)` → reserva espaço para 5 caracteres.
  - É útil quando os valores possuem tamanho fixo.
  - Exemplo: `CEP`, códigos ou siglas de tamanho definido.
  - 1 até 5

- **VARCHAR(n)** → armazena uma quantidade **variável** de caracteres, limitada ao tamanho definido.
  - Exemplo: `VARCHAR(100)` → pode armazenar até 255 caracteres.
  - Ocupa espaço de acordo com o conteúdo armazenado, além de um pequeno overhead.
  - O limite máximo depende do **SGBD**.

- **TEXT** → usado para armazenar **textos maiores**.
  - O tamanho máximo depende do **SGBD**.
  - É indicado para textos que podem ser muito maiores que um `VARCHAR`.
  - 255 até 65000

- **LONGTEXT** → usado para armazenar textos extremamente grandes.
  - Disponível em alguns SGBDs, como o **MySQL**.

---

## Por que não usar `TEXT` para todos os campos?

Porque devemos escolher o tipo de dado de acordo com a **necessidade do campo**.

- `CHAR` → quando o tamanho é **fixo**.
- `VARCHAR` → quando o tamanho é **variável** e existe um limite conhecido.
- `TEXT` → quando precisamos armazenar **textos maiores**.

> **Importante:** `TEXT` não significa simplesmente "reservar todo o tamanho máximo para cada registro". O armazenamento real depende do SGBD e do conteúdo. A escolha do tipo deve considerar **tamanho, finalidade, desempenho e recursos do SGBD**.

---

## Diferença principal

- **CHAR** → tamanho **fixo**
- **VARCHAR** → tamanho **variável**
- **TEXT** → texto **maior**
- **LONGTEXT** → texto **muito grande**

### Exemplo

```text
CHAR(5)
"ABC  "
↓
Tamanho fixo

VARCHAR(5)
"ABC"
↓
Tamanho variável

TEXT
"Um texto que pode ser muito maior..."
↓
Textos maiores

## Tipos especiais

Usados principalmente para representar **datas, horários e conjuntos de valores pré-definidos**.

---

## Formato

* **DATE** → armazena apenas uma data.

  * Formato: `YYYY-MM-DD`
  * Exemplo: `2026-09-01`

* **DATETIME** → armazena **data + horário**.

  * Exemplo: `2026-09-01 22:30:00`

* **TIMESTAMP** → armazena **data + horário**, sendo muito usado para registrar momentos de criação ou alteração de registros.

  * Exemplo: `2026-09-01 22:30:00`

* **TIME** → armazena apenas um **horário**.

  * Exemplo: `22:30:00`

* **ENUM** → permite escolher **apenas um valor** entre várias opções previamente definidas.

  * Exemplo: `ENUM('Pendente', 'Pago', 'Cancelado')`
  * Um registro pode ter **somente uma** dessas opções.
  * Exemplo: `status = 'Pago'`

* **SET** → permite escolher **um ou vários valores** entre opções previamente definidas.

  * Exemplo: `SET('Português', 'Inglês', 'Espanhol')`
  * Um registro pode ter **uma, várias ou nenhuma** dessas opções.
  * Exemplo: `idiomas = 'Português, Inglês'`

---

### Diferença principal

**ENUM → escolhe 1 opção**

**SET → pode escolher várias opções**

### Exemplo

```text
ENUM → Status: Pendente | Pago | Cancelado
        ↓
        Apenas 1 opção

SET → Hobbies: Futebol | Música | Jogos | Leitura
       ↓
       Pode escolher várias opções
```

> **Resumo:** `ENUM` trabalha com **uma única opção** de um conjunto definido. `SET` permite **múltiplas opções** do conjunto definido.
